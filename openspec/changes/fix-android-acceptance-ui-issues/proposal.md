## Why

2026-09-13/14 的 Android 全量验收在播放层之外还发现了一组界面问题。其中三处直接违反已有 spec：插件搜索里重复加入曲目不告知「已在曲库中」（`plugin-source`「重复加入同一曲目」）、未声明更新地址的插件把「更新」入口整个藏起来而不说明原因（`plugin-source`「按插件自述地址更新」）、下载结果显示在与之无关的歌单页上（`offline-cache`「批量中单首失败」要求告知的是**这批**曲目）。其余几处不违反 spec 字面，但影响可用性：带输入框的底部面板被软键盘整个挡住、歌单序号到三位数就断成两行、几段说明文案里夹着多余空格。

这些问题彼此独立、各自很小，但都是「实现没有照已定的行为做」，不涉及任何新行为，适合合并成一次修复、一次验收。

## What Changes

- **插件搜索重复加入时告知**：与榜单、歌单详情、链接导入三处已有的做法一致，显示「「标题」已在曲库中。」。三处重复的「加入 + 提示」逻辑合并为一个共用实现。
- **插件搜索开始新搜索时清掉上一次的失败条目**：加载中不再显示上一次搜索的失败信息。
- **未声明更新地址的插件显示不可用的「更新」入口并说明原因**。
- **歌单页的下载结果只统计本歌单的曲目**：在别处发起的下载不再显示为本歌单的「已下载 N 首」。
- **带输入框的底部面板在软键盘弹出时整体上移**：新建/重命名歌单、导入音乐（远程地址、播放列表地址）、从地址安装插件、插件变量设置、链接导入等所有面板一并生效。
- **歌单序号列按歌单规模定宽**：三位数、四位数序号不再换行，同一歌单内各行对齐。
- **修正 JSX 文本换行造成的多余空格**：插件风险说明、插件管理页空状态与版本确认、插件搜索无可用插件提示，共 5 处。
- **风险告知在标记读取完成前不放行**：修复「读取尚未返回时点击安装会跳过风险告知」的窗口。
- **「未知专辑」卡片不再借用某一首曲目的封面与艺术家**：无专辑信息的曲目聚合在一起，不是一张专辑，卡片以统一占位封面与曲目数展示。

### 非目标

- **播放失败处理与缓冲显示**：属于 `fix-playback-failure-handling`，根因在播放层。
- **长列表快速滚动空白**：属于 `improve-long-list-scroll`，需要先用 release 包复核。
- **同名专辑按艺术家拆分**：正交。专辑目前按名称聚合，不同艺术家的同名专辑（如「Greatest Hits」）会合并，这是分组键的语义问题，需要先决定是否引入「专辑艺术家」字段，与本 change 的展示修正无关。
- **卸载插件前的二次确认**：spec 未要求，本轮验收也未将其列为问题。
- **引入第三方键盘处理库**：未采纳，理由见 design.md 决策 2。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

无。本 change 修正的都是实现与既有 spec（`plugin-source`、`offline-cache`、`playlist`、`music-library`）不一致或可用性问题，不改变任何 spec 层面的行为，因此 `.openspec.yaml` 声明 `skip_specs: true`。

## Impact

- **`src/plugins/screens/search.android.tsx`、`discovery-tracks.android.tsx`、`discovery-import.android.tsx`**：改用共用的候选曲目加入逻辑；搜索页在新搜索开始时清除失败条目。
- **`src/plugins/screens/manage.android.tsx`**：更新入口的不可用态与说明；风险告知标记的读取状态；两处文案。
- **`src/plugins/ui/risk-notice.tsx`**：文案空格。
- **`src/cache/queue.ts`、`src/app/playlist/[id].tsx`**：本轮下载结果携带曲目标识，歌单页按本歌单曲目过滤。
- **`src/ui/sheet.tsx`**：键盘避让，所有底部面板统一受益。
- **`src/ui/indexed-track-row.tsx`、`src/app/playlist/[id].tsx`**：序号列宽度。
- **`src/library/store.ts`**：「未知专辑」分组的展示字段。
- **不触及**：播放层、来源层、数据库结构、原生代码。
