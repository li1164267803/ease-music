## 2. 四处来源

- [x] 2.1 新建 `src/lyrics/sources.ts`：四处来源的统一取法，优先级为**歌词目录 > 内嵌 > 来源插件 > 歌词类插件**（design 决策 1）
- [x] 2.2 内嵌歌词：复用 `parseAudioMetadata`，读 `common.lyrics`（同步与非同步两种都要处理）
- [x] 2.3 歌词目录：用 `Directory.pickDirectoryAsync` 取得授权，目录路径存进 `src/domain/settings.ts` 的 KV 配置（不为一个字符串建表）
- [x] 2.4 目录内按**曲目标题**匹配，依次尝试 `<title>.lrc`、`<title> - <artist>.lrc`、`<artist> - <title>.lrc`；**不得按文件名匹配**（design 决策 2，实测本地曲目的 fileName 常是 `msf:19` 这类文档编号）
- [x] 2.5 读取 `.lrc` 时若解码失败或结果含大量替换字符，判定为非 UTF-8 并返回可识别的失败原因，**不返回乱码**（design 决策 5）
- [x] 2.6 **来源插件**歌词：经既有的 `invokePlugin` 对曲目自己的 `mediaItem` 调 `getLyric`（一步，精确）
- [x] 2.6b **歌词类插件**歌词（design 决策 2）：筛出 `supportedSearchType` 含 `'lyric'` 的已安装插件，先 `search(标题, 1, 'lyric')` 取候选、再对第一条候选 `getLyric`（两步，按标题匹配）。**对任意曲目适用**，包括本地文件与远程直链——这是覆盖面最大的一路
- [x] 2.6c 歌词正文取 `rawLrc` 字段（MusicFree 既有约定，实测三个已安装插件都用它）；字段缺失或非字符串按「这一路没取到」处理，不抛给用户
- [x] 2.6d 两类插件的故障都按 plugin-source spec 处理——不影响宿主、不打扰用户
- [x] 2.7 任一处失败都不中断其余来源，也不影响播放

>
> **验收记录（2026-09-10，Android 模拟器 Medium_Phone_API_36.0，dev client 连 Metro）**：全部通过。补充说明：
>
> - 6.1 内嵌歌词：设备上没有自带歌词标签的音频，用 mutagen 给一个 MP3 写入 SYLT（毫秒时间戳）后经导入流程重新入库验证
