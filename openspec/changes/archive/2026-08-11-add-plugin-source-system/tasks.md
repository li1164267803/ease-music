### 11.5 已记录的兼容性事实

| 观察 | 处置 |
| --- | --- |
| 歌词类插件声明 `supportedSearchType: ["lyric"]`，但同样实现了 `search` | **已修**：筛选搜索来源改看「声明支持 music」，未声明按协议缺省视为支持。此前只看有无 `search` 方法，会拿 `music` 去调歌词插件并报一条本不该出现的错误 |
| 「网易音乐」的 `duration` 返回**毫秒**，而协议写明 `/** 时长(s) */` | **不在宿主侧兜底**，由插件侧修正。宿主一旦开始猜单位，「协议说了什么」就不再是唯一依据，且每层猜测都会在守规范的插件上制造新误判 |
| 曲目字段命名与协议一致：`id` / `title` / `artist` / `album` / `artwork` | 无需改动，当初只认协议字段的判断成立 |
| 插件在模块顶层发起未捕获的请求，失败后成为未处理 rejection | 不缓解，见 design.md Risks。dev 下弹 LogBox，release 不崩溃 |
| `appVersion` 声明的是「适配的 MusicFree 版本」，与本应用版本号不同命名空间 | 「网易音乐」因此被判为不兼容并显示警告——正是决策「只提示不拦截」预判的误报。**警告文案与去留待定，见下** |

**待定**：`appVersion` 警告在真实插件上大概率是误报（版本号命名空间不同）。一条经常是错的警告会训练用户忽略所有警告。是改文案、还是只在开发者视图里显示、还是撤掉，需要产品决策。
