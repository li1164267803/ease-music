## 2. 解析器（纯函数，可单测）

- [x] 2.1 新建 `src/library/m3u.ts`，实现「播放列表文本 + 基准地址 → 条目列表 + 跳过项」的解析入口
- [x] 2.2 解析 `#EXTINF:<秒数>,<艺人> - <标题>`：取时长、艺人、标题；时长为 `-1` 或非数字时置空；描述不含「艺人 - 标题」分隔时整体作为标题
- [x] 2.3 忽略空行与除 `#EXTINF` 外的所有 `#` 开头行；保持条目在文件中的原始顺序

- [x] 2.7 编码处理：跳过 UTF-8 BOM；UTF-8 解码失败时尝试中文本地编码，仍失败则放弃该条目的标题与艺人、回退为从地址推断，绝不写入乱码（决策 4）
- [x] 2.8 单测覆盖：带/不带 `#EXTINF`、时长 `-1`、无艺人分隔、相对地址、非 http 协议、畸形行、HLS 文件、UTF-8 带 BOM、非 UTF-8 中文、空文件与非播放列表文本

## 5. Android 验收

- [x] 5.1 导入一个带 `#EXTINF` 的远程播放列表 → 曲目标题、艺人、时长正确，顺序与文件一致
- [x] 5.2 导入一个纯地址列表（无 `#EXTINF`）→ 标题从地址末段推断，全部入库
- [x] 5.3 导入一个含相对路径的远程播放列表 → 地址正确拼接，曲目可播放

- [x] 5.5 导入一个 HLS `.m3u8` → 提示为流媒体播放列表，曲库与歌单均无新增
- [x] 5.6 导入一个非 UTF-8 编码的中文播放列表 → 中文标题正确，或退化为地址推断的标题，无乱码 —— **实测走的是退化分支**：Hermes 不带 gb18030 表，标题回退为地址推断、艺人留空、时长正确，无乱码（决策 4 的最坏情况）

- [x] 5.10 远程播放列表地址不可达 → 报告失败原因，曲库与歌单均无新增
- [x] 5.11 导入的曲目参与检索、加入其他歌单、播放、下载到本地 → 与手动添加的远程地址曲目行为一致
